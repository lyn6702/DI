# 📒 흩어진 테이블, 하나의 인사이트로 — 정리노트

> ⭐ **핵심 한 줄:** 합치기 전에 **키부터 검증**한다. 무턱대고 합치면 행이 불어나거나 사라져도 모른다.

```text
concat → merge → 키 검증 → groupby+agg → transform → pivot_table
(이어붙이기) (키로 연결) (합치기 전 점검) (그룹 요약)   (행에 되돌리기) (모양 바꾸기)
```

---

## 0. 키(key)란?

- 표와 표를 잇는 **공통 열** (엑셀의 VLOOKUP)
- 예: `orders`의 `customer_id` ↔ `customers`의 `customer_id`

| 테이블 | 한 행의 뜻 | 키 |
|---|---|---|
| orders | 주문 1건 | customer_id, product_id |
| customers | 고객 1명 | customer_id |
| products | 상품 1종 | product_id |

---

## 1. concat — 같은 모양 이어 붙이기

- **같은 모양(컬럼)**의 표를 **그냥 갖다 붙임** (키로 짝짓지 않음)
- 종이를 풀로 이어 붙이는 것
- 항상 `pd.concat([표1, 표2])` (리스트로 넘김)

| 옵션 | 뜻 |
|---|---|
| `axis=0` (기본) | **위아래**로 쌓기 → **행** 늘어남 |
| `axis=1` | **좌우**로 붙이기 → **열** 늘어남 |
| `ignore_index=True` | 인덱스를 0부터 다시 매김 |
| `keys=[...]` | 어느 조각에서 왔는지 라벨 |

- ⚠️ 컬럼 이름이 다르면 → **NaN** 생김
- 컬럼이 서로 다른 표 → concat ❌ → **merge** ⭕

---

## 2. merge — 키로 연결하기 ⭐

- **서로 다른 정보**를 **공통 키**로 짝지어 합침
- 형태: `pd.merge(왼쪽, 오른쪽, on="키", how="조인유형")`

### 조인 유형 4가지 ⭐⭐

| how | 뜻 | 남는 행 |
|---|---|---|
| `inner` (**기본값**) | 교집합 | **양쪽 모두** 있는 키만 |
| `left` | 왼쪽 기준 | **왼쪽 전부** + 오른쪽은 맞는 것만 |
| `right` | 오른쪽 기준 | 오른쪽 전부 + 왼쪽은 맞는 것만 |
| `outer` | 합집합 | **한쪽에라도** 있으면 전부 |

### 예시로 외우기

왼쪽 키 = A, B, C / 오른쪽 키 = B, C, D

| how | 결과 키 | 행 수 |
|---|---|---|
| inner | B, C | 2 |
| left | A, B, C (A는 NaN) | 3 |
| right | B, C, D (D는 NaN) | 3 |
| outer | A, B, C, D | 4 |

- 짝이 없으면 그 자리는 **NaN**
- `how` 선택 = **어떤 행을 남기고, 어디에 결측을 만들지**의 결정
- 실무에선 주문 기록을 다 살리는 **left**를 가장 많이 씀

### merge vs join vs concat

| 도구 | 기준 |
|---|---|
| `merge` | **키 컬럼**으로 합치기 |
| `join` | **인덱스**로 합치기 |
| `concat` | **같은 모양** 이어 붙이기 |

## 3. 병합 전 키 검증 ⭐⭐⭐

### 병합 사고 2가지

| 사고 | 원인 | 결과 |
|---|---|---|
| **행 폭증** (row explosion) | **오른쪽**에 같은 키가 여러 번 | 왼쪽 행이 복제 → 매출 부풀려짐 |
| **조용한 결측** | 왼쪽 키가 오른쪽에 **없음** | left 조인에서 NaN 발생 |

- 오른쪽에 같은 키가 **n개** → 왼쪽 그 행이 **n줄**
- 왼쪽 키 중복은 정상 (한 고객이 여러 주문)
- 둘 다 **에러 없이 조용히** 일어남 → 그래서 검증 필수

### 관계 종류

| 관계 | 뜻 | 예 |
|---|---|---|
| 1:1 | 양쪽 키 모두 유일 | — |
| N:1 (m:1) | 왼쪽 여러 개 : 오른쪽 하나 | 주문 : 고객 |
| N:N (m:m) | 양쪽 다 중복 | ⚠️ 위험, 곱셈으로 폭증 |

- **유일해야 할 쪽** = 한 줄이 "그 대상 하나"인 표 (고객 목록, 상품 목록)

### 검증 도구 ⭐

| 확인 | 도구 | 막는 것 |
|---|---|---|
| 키 중복 | `duplicated().sum()` | 행 폭증 |
| 짝 없는 키 | `~왼쪽["키"].isin(오른쪽["키"])` | 조용한 결측 |
| 관계 검증 | `validate="m:1"` | 어기면 **MergeError** |
| 출처 표시 | `indicator=True` | `_merge` 열로 확인 |

### validate 관계 코드

`"1:1"` · `"1:m"` · `"m:1"` · `"m:m"` (왼쪽:오른쪽 순서)

### indicator=True 의 `_merge` 값

| 값 | 뜻 |
|---|---|
| `both` | 양쪽 매칭 |
| `left_only` | 왼쪽에만 → **조용한 결측 생긴 행** |
| `right_only` | 오른쪽에만 |

- 에러가 나는 게 **다행** → 부풀려진 보고서보다 낫다
- 검증 결과도 **기록**: "키는 ○○, 관계는 m:1, 중복 0·미매칭 0"

## 4. groupby + agg — 그룹별 요약 ⭐

### split-apply-combine

| 단계 | 하는 일 |
|---|---|
| **Split** | 기준 열로 쪼갠다 |
| **Apply** | 각 그룹에 같은 계산 |
| **Combine** | 결과를 다시 한 표로 |

### 패턴

| 패턴 | 형태 |
|---|---|
| 기본 | `groupby("기준")["대상"].mean()` |
| 여러 함수 | `.agg(["mean", "sum", "count"])` |
| 이름 지정 | `.agg(매출=("amount", "sum"))` |
| 여러 기준 | `groupby(["region", "membership"])` |

- `agg` = 여러 통계를 **한 번에** + 결과 컬럼 **이름 지정**
- 이름 지정 형태: **`결과이름=(대상열, 함수)`**
- 여러 기준으로 묶음 → **교차 그룹** → `unstack()`으로 교차표

### 자주 쓰는 집계

| 함수 | 뜻 |
|---|---|
| `count` | 개수 (NaN 제외) |
| `nunique` | **고유** 개수 (서로 다른 고객 수) |
| `pct_change()` | 직전 행 대비 **변화율** (첫 행은 NaN) |
| `idxmax()` | 최댓값의 **이름표** |

## 5. transform — 그룹 통계를 행에 되돌리기 ⭐⭐

- 🧠 **agg는 접고, transform은 펼친다**

| | agg | transform |
|---|---|---|
| 결과 행 수 | **그룹 수** (줄어듦) | **원본과 동일** |
| 용도 | 요약표 | 원본에 **컬럼 추가** |
| 활용 | 보고서 | 그룹 내 비중·편차 |

- 같은 그룹 행에는 **같은 값**이 채워짐

### 단골 활용 2가지

| 활용 | 계산 |
|---|---|
| **그룹 내 비중** | 각 행 ÷ 그룹 합계 (`transform("sum")`) |
| **그룹 내 편차** | 각 행 − 그룹 평균 (`transform("mean")`) |

- 비중은 **반드시 transform** → 분모(그룹 합)를 각 행에 돌려줘야 하니까
- 한 그룹의 비중을 다 더하면 **100%** (검산)
- 결측치 그룹별 대체에도 사용 (원래 길이라 `fillna`에 바로 넣을 수 있음)
- 머신러닝 **피처 엔지니어링**에서 자주 씀

## 6. pivot_table & wide/long ⭐

| 형태 | 모양 | 유리한 곳 |
|---|---|---|
| **long** | 한 행 = 한 조합, 세로로 김 | **저장·집계·시각화** |
| **wide** | 한 축을 열로 펼침 | **사람이 보기** (보고서) |

🧠 **보여줄 땐 wide, 저장·그릴 땐 long**

### 변환 도구

| 도구 | 방향 |
|---|---|
| `pivot_table` | long → **wide** |
| `melt` | wide → **long** |
| `unstack` | 인덱스 → 열 |
| `stack` | 열 → 인덱스 |

### pivot_table 인자 ⭐

| 인자 | 정하는 것 |
|---|---|
| `index` | **행** |
| `columns` | **열** |
| `values` | 칸에 들어갈 **값** |
| `aggfunc` | 집계 방법 (기본 **평균**) |
| `margins=True` | 합계(**All**) 행·열 추가 |
| `fill_value=0` | 빈칸을 0으로 |

- `pivot_table` = **groupby + unstack**을 한 번에
- `pivot`은 집계 없음 → 같은 칸에 값이 2개면 에러
- 엑셀 피벗테이블과 같은 개념

---

## 7. 종합 실습 흐름

1. **키 검증** → 중복·미매칭 0건 확인
2. **병합** → `validate="m:1"`, 병합 후 행 수 = 원본 주문 수
3. **월별 KPI** → 총매출, 주문 건수, 객단가, 구매 고객 수(`nunique`)
4. **교차표 + 점유율** → `pivot_table` + `transform`
5. **보고서** → 발견 + **근거** + 제언

- **객단가** = 총매출 ÷ 주문 건수
- 매출 변동 원인 = **고객 수 ↑** vs **객단가 ↑** 로 분해

---

## 8. 상황별 도구 고르기

| 상황 | 도구 |
|---|---|
| 같은 양식의 파일 여러 개 | `concat` |
| 정보가 여러 표에 흩어짐 | 키 검증 → `merge` |
| 병합 후 행이 불어남 | 키 중복 확인 → `validate="m:1"` |
| 그룹별 요약 | `groupby` + `agg` |
| 그룹 통계를 원본에 붙이기 | `transform` |
| 보고용 교차표 | `pivot_table` |

## ✅ 빈칸 퀴즈

| 질문 | 답 |
|---|---|
| 같은 모양 표를 위아래로 이어 붙이는 함수 | `concat` |
| concat에서 열이 늘어나는 axis | `axis=1` |
| merge의 기본 how | `inner` |
| 왼쪽 전부 + 오른쪽은 맞는 것만 | `left` |
| 양쪽 어디든 있으면 전부 | `outer` |
| left 조인에서 오른쪽 짝이 없으면 | NaN |
| 인덱스로 합칠 때 편한 것 | `join` |
| 오른쪽 키 중복 시 생기는 현상 | 행 폭증 |
| 행 폭증을 에러로 막는 인자 | `validate="m:1"` |
| 짝 없는 행을 추적하는 인자 | `indicator=True` |
| `_merge`의 `left_only` 뜻 | 왼쪽에만 있음 (조용한 결측) |
| groupby의 세 단계 | split → apply → combine |
| 결과 컬럼 이름까지 정하는 집계 | `agg(이름=("열", "함수"))` |
| 서로 다른 고객 수 | `nunique` |
| 결과 행 수가 원본과 같은 것 | `transform` |
| 그룹 내 비중 계산 도구 | `transform("sum")` |
| long → wide | `pivot_table` |
| wide → long | `melt` |
| 합계 행·열 추가 옵션 | `margins=True` |
| pivot_table의 기본 aggfunc | 평균(mean) |
