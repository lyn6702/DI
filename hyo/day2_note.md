# 📒 결측치에도 이유가 있다 — 정리노트

> ⭐ **핵심 한 줄:** "왜 이 방법을 골랐는가"를 한 줄로 적을 수 없다면, 그 처리는 하지 않은 것보다 위험하다.

```text
인덱싱 → 필터링 → 결측 진단 → 결측 유형 → 결측 처리 → IQR 탐지 → 이상치 처리
(가리키기) (고르기)  (어디가)     (왜)        (어떻게)   (얼마나)    (제거?유지?)
```

---

## 1. 인덱싱 3종 ⭐

| 방식 | 기준 | 비유 | 예 |
|---|---|---|---|
| `.loc` | **라벨**(이름) | 주소로 부르기 | `df.loc[5, "age"]` |
| `.iloc` | **위치**(번호) | N번째 칸 | `df.iloc[5, 1]` |
| 불리언 | **조건** | 조건 맞는 사람 전원 | `df[조건]` |

### 슬라이스 끝 포함 함정 ⭐⭐

| | 결과 | 개수 |
|---|---|---|
| `.loc[0:5]` | 0~5 (끝 **포함**) | 6개 |
| `.iloc[0:5]` | 0~4 (끝 **미포함**) | 5개 |

🧠 **라벨은 끝 포함, 위치는 끝 미포함**

### 값 바꾸기 표준 패턴

- `df.loc[조건, "열"] = 값` → 조건 맞는 행의 그 열만 바꾸기
- 이상한 값은 일단 **NaN으로 표시** → 처리 방침은 따로 정한다
- `df["열"][조건] = 값`(체이닝)은 경고가 뜨고 적용 안 될 수 있음 → **쓰지 말 것**

## 2. 불리언 필터링 심화

| 도구 | 뜻 | 대신하는 것 |
|---|---|---|
| `isin([...])` | 여러 값 중 하나인가 | `==` 여러 개를 `|`로 연결 |
| `between(a, b)` | a 이상 b 이하인가 (양끝 포함) | `>=` & `<=` |
| `query("...")` | 문자열로 조건 쓰기 | 긴 `df[(...) & (...)]` |
| `~` | 반대 (NOT) | — |

- 조건 묶기: `&`(그리고), `|`(또는) → **각 조건은 괄호로**
- 파이썬의 `and`/`or`는 쓰면 안 됨 (`query` 안에서만 가능)
- `isin`·`between` → **불리언** 반환 / `query` → **걸러진 표** 반환

### 결측의 함정 ⭐⭐ 오늘 가장 중요

- `NaN > 0` → **False**, `NaN <= 0` → **False**
- NaN과의 비교는 **항상 False**
- 그래서 조건 필터를 걸면 결측이 **조용히 사라진다**
- 필터 결과에 결측이 안 보여도 "결측 없음"이라고 결론 내리면 안 됨 → `isnull().sum()`으로 따로 확인
- 해결: `notna()` / `isnull()`로 결측을 **명시적으로** 포함·제외

## 3. 결측 패턴 진단

### 진단 5종 세트

| 도구 | 알려주는 것 |
|---|---|
| `isnull().sum()` | 열별 결측 **개수** |
| `isnull().mean()` | 열별 결측 **비율** |
| `isnull().sum(axis=1)` | **행별** 결측 개수 |
| `df[df["열"].isnull()]` | 그 열이 빈 행들 |
| 결측 히트맵 (missingno) | 결측 분포를 그림으로 |

### 결측 비율 기준

| 비율 | 판단 |
|---|---|
| **5% 이하** | 영향 작음, 비교적 자유롭게 처리 |
| **30% 이상** | 그 열의 쓸모 자체를 의심 |

### 패턴 3가지

| 패턴 | 의미 |
|---|---|
| 한 열에만 흩어짐 | 그 열만 단독 처리 |
| 두 열이 같은 행에서 빔 | 같은 원인 의심 |
| 특정 그룹에 쏠림 | 수집 과정에 원인 |

## 4. 결측 유형 ⭐⭐⭐

| 유형 | 풀네임 | 원인 | 시험 답안지 비유 |
|---|---|---|---|
| **MCAR** | Missing **Completely** At Random | **완전 무작위** | 인쇄 오류로 문항이 안 보임 |
| **MAR** | Missing At Random | **다른 열**이 원인 | 외국인이 한국어 지문을 비움 (국적 열) |
| **MNAR** | Missing **Not** At Random | **비운 값 자체**가 원인 | 모르는 학생이 비움 (값 = 낮은 점수) |

### 진단 신호 → 처리

| 유형 | 진단 신호 | 추천 처리 | 피할 처리 |
|---|---|---|---|
| MCAR | 다른 열과 상관 없음 | 제거, 단순 대체 | — |
| MAR | 특정 그룹에서 결측 비율이 다름 | **그룹별 대체** | 전체 평균 대체 |
| MNAR | 다른 열로 설명 안 되는 쏠림 | **결측 플래그** 보존 | 평균·중앙값 대체 |

### 예시

- 결측 행의 지역 분포 ≈ 전체 분포 → **MCAR**
- app 채널에서 금액 결측이 더 많음 → **MAR**
- 고소득(VIP)일수록 소득을 안 적음 → **MNAR**

- 세 유형은 100% **증명 불가** → 데이터 신호 + 도메인 지식으로 **추정**하고 **기록**
- MNAR은 데이터만으로 확인이 어려워 **도메인 지식**에 더 의존

## 5. 결측 처리 전략 ⭐⭐

### 두 갈래

1. **제거** (Deletion) — `dropna()`
2. **대체** (Imputation) — `fillna()`
   - 단순 대체: 평균 · 중앙값 · 최빈값 · 고정값
   - 그룹별 대체: 같은 그룹의 통계량
   - 시간 기반: 앞 값 / 뒤 값으로 채움

### 방법별 언제 쓰나

| 방법 | 언제 |
|---|---|
| 제거 `dropna` | 결측 **5% 이하** + MCAR + 행 충분 |
| 평균 | 분포가 **좌우 대칭** (이상치에 약함) |
| 중앙값 | 분포가 **한쪽으로 쏠림** (금액·소득·수량) |
| 최빈값 | **범주형** (성별·등급) |
| `'unknown'` | 결측 자체가 신호일 때 |
| 그룹별 대체 `transform` | **MAR** |
| `ffill` / `bfill` | **시계열**, 짧은 결측 |
| 결측 플래그 | **MNAR** 의심 |

### 의사결정 흐름 (외우기)

| 상황 | 처리 |
|---|---|
| 5% 이하 + MCAR | 행 제거 |
| 수치형 + MAR | 그룹별 중앙값 |
| 수치형 + MCAR + 쏠림 | 중앙값 |
| 범주형 + 결측 적음 | 최빈값 또는 'unknown' |
| MNAR 의심 | 플래그 컬럼 + 단순 대체 피하기 |
| 시계열 짧은 결측 | ffill / bfill |

### 원칙

- `transform`은 그룹 통계를 **원래 행 길이**로 돌려줌 → `fillna`에 바로 넣을 수 있음
- **원본 직접 수정 금지** → `.copy()`로 사본에 처리
- 진단 없이 `fillna(0)` 금지 → 왜 0인지 설명 불가

## 6. IQR 이상치 탐지 ⭐⭐

### 공식 (꼭 외우기)

| 이름 | 공식 |
|---|---|
| **IQR** | Q3 − Q1 |
| **하한** | Q1 − 1.5 × IQR |
| **상한** | Q3 + 1.5 × IQR |

→ 하한~상한 **밖**이면 이상치

### 용어

| 기호 | 뜻 |
|---|---|
| Q1 | 25% 지점 (1사분위) |
| Q2 | 50% 지점 = **중앙값** |
| Q3 | 75% 지점 (3사분위) |
| IQR | 가운데 **50%**의 폭 |

- **1.5인 이유**: 통계학자 튜키(1977)가 정한 **합의된 기준** (절대 법칙 X, 엄격하게는 3)
- 박스플롯 **상자 = Q1~Q3**, **수염 = 1.5×IQR**, 수염 밖 점 = 이상치
- 수식과 박스플롯은 **같은 정보**

### 강점 vs 한계

| 강점 | 한계 |
|---|---|
| 분포 가정 필요 없음 | 쏠린 분포(매출·소득)에선 과하게 잡음 |
| 계산 간단, 박스플롯과 호환 | **원인**은 알려주지 못함 |
| 1.5라는 합의 기준 | 비즈니스 기준과 다를 수 있음 |

- **수치형에만** 사용 (범주형 X → 빈도 분석으로)
- 참고: **Z-점수** |z| > 3 → 이상치. 정규분포 **가정이 필요**한 게 IQR과의 차이

## 7. 이상치 처리 의사결정 ⭐⭐

### 이상치의 정체 3가지

| 정체 | 예 | 처리 |
|---|---|---|
| **입력 실수** | 999살, 단위 오류 | NaN 표시 → 결측 처리 |
| **진짜 극단** | VIP 대량 주문 | **유지** (세그먼트 분리) |
| **신호** | 부정 거래, 고장 직전 | **유지** (분석 핵심 대상) |

### 처리 옵션 3종

| 옵션 | 방법 | 언제 |
|---|---|---|
| **제거** | NaN 표시 → 결측 처리 | 물리적으로 불가능 (음수 나이, 999살) |
| **클리핑** | 경계값으로 자름 `clip` | 분포는 살리고 극단 영향만 줄일 때 |
| **유지 + 플래그** | 그대로 두고 표시 열 추가 | 진짜 극단, 판단 보류 |

### 판단 순서

1. 물리적으로 불가능? → **제거**
2. 단위 입력 실수 의심? → 원본 추적 후 제거 또는 클리핑
3. 진짜 큰 거래 (B2B, VIP)? → **유지 + 플래그**
4. 이상치 자체가 분석 대상? → **유지** (절대 제거 X)
5. 모르겠다 → **유지 + 플래그** (기본값)

> 🧠 **결정 못 하면 유지 + 플래그** — 정보를 지우지 않는 게 가장 안전
> ⚠️ **"IQR로 잡혔으니 다 빼자" = 가장 위험한 실수**
> 💡 이상치 처리는 결국 **결측 처리로 흡수**된다 (NaN 표시 → fillna)

## 8. 기록 습관 — 3줄 메모 ⭐

| 항목 | 내용 |
|---|---|
| **결정** | 무엇을 어떻게 처리했나 |
| **근거** | 왜 그렇게 판단했나 |
| **한계** | 무엇을 확인 못 했나 |

- 원본은 두고 **사본**에 처리
- 처리 코드는 셀로 분리 → 언제든 **재처리 가능**하게

## ✅ 빈칸 퀴즈

| 질문 | 답 |
|---|---|
| `.loc[0:3]`의 행 개수 | 4개 (끝 포함) |
| `.iloc[0:3]`의 행 개수 | 3개 (끝 미포함) |
| 조건 맞는 행의 특정 열만 바꾸는 패턴 | `df.loc[조건, "열"] = 값` |
| `NaN > 0`의 결과 | False |
| 여러 값 중 하나인지 검사 | `isin` |
| 행별 결측 개수 | `isnull().sum(axis=1)` |
| 완전 무작위 결측 | MCAR |
| 다른 열로 설명되는 결측 | MAR |
| 비운 값 자체가 원인인 결측 | MNAR |
| MAR에 추천하는 처리 | 그룹별 대체 |
| MNAR에서 피할 처리 | 단순 평균 대체 |
| 쏠린 분포에 안전한 대체값 | 중앙값 |
| 범주형 결측 대체값 | 최빈값 |
| 시계열 짧은 결측 | ffill / bfill |
| IQR 상한 공식 | Q3 + 1.5 × IQR |
| IQR을 쓸 수 없는 자료형 | 범주형 |
| 999살 처리 | 제거 (NaN 표시) |
| 이상치 판단 불가 시 기본값 | 유지 + 플래그 |
| 처리 기록 3줄 | 결정 · 근거 · 한계 |
