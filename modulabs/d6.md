# 🧹 전처리 파이프라인 — 품질 리포트

## 1. 행 수 변화

| 항목 | 값 |
|---|---|
| 입력 행 수 | 1,500 |
| 출력 행 수 | 1,404 |
| 제거된 행 | 96행 (**6.4%**) |

- 제거 비율이 6.4%로, 이상치·결측 행을 걸러내면서도 표본 손실을 작게 유지함

## 2. 컬럼별 결측 비율 (상위 5개)

**처리 전**

| 컬럼 | 결측 수 | 비율 |
|---|---|---|
| amount | 60 | 4.0% |
| grade_apply | 60 | 4.0% |
| grade_vec | 60 | 4.0% |
| age_next_year_apply | 30 | 2.0% |
| customer_age | 30 | 2.0% |

**처리 후**

| 컬럼 | 결측 수 | 비율 |
|---|---|---|
| membership_score | 1 | 0.07% |
| order_id | 0 | 0% |
| region | 0 | 0% |
| customer_age | 0 | 0% |
| channel | 0 | 0% |

- 처리 전 결측이 있던 `amount`, `customer_age` 등은 처리 후 모두 0건
- `membership_score`에 결측 1건이 남아 있음 → 원인 확인 필요

## 3. 새로 만들어진 컬럼

| 항목 | 값 |
|---|---|
| 처리 전 컬럼 수 | 22 |
| 처리 후 컬럼 수 | 40 |
| 새 컬럼 (파생 + 인코딩) | **18개** |

## 4. 자료형 분포 (처리 후)

| 자료형 | 컬럼 수 |
|---|---|
| int64 (정수) | 17 |
| float64 (실수) | 12 |
| object (문자열) | 11 |
| **합계** | **40** |

- 원-핫 인코딩 컬럼(0/1)이 늘어나 정수형(int64)이 가장 많음
- 문자열(object) 11개는 모델에 넣기 전 인코딩하거나 제외해야 함
